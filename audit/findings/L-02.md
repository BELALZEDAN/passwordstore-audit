### [L-02] Missing Input Validation for Password (Weak Input Constraints + UX Risk)

## Description

The `setPassword` function accepts a `string` input without enforcing any validation rules such as minimum length, maximum length, or non-emptiness. As a result, the contract allows setting an empty string or arbitrarily large strings as the password.

While Solidity itself does not enforce semantic constraints on string inputs, the absence of validation can lead to unintended states that reduce the usability and reliability of the contract.

## Impact

- The owner may accidentally set an empty password, defeating the purpose of password storage.
- Extremely large strings may increase gas costs unnecessarily.
- Downstream integrations or frontends may break or behave unexpectedly if they assume basic password constraints.

This issue does not directly introduce a security vulnerability but represents a quality and robustness concern.

## Proof of Concept
```javascript
passwordStore.setPassword("");
```

The contract accepts the empty string without reverting, resulting in a password value that may be unintended.

## Recommended Mitigation

Add basic input validation to enforce reasonable constraints, for example:

- Reject empty passwords
- Optionally enforce minimum and/or maximum length limits

Example mitigation:
```javascript
require(bytes(newPassword).length > 0, "Password cannot be empty");
```

Additional constraints may be added depending on the intended use case.
