### [L-03] Event Emitted Without Relevant Context

## Description

The contract emits the `SetNetPassword` event whenever the password is updated. However, the event does not include any contextual information such as the caller address or a reference to the updated value (e.g., a hash of the password).

While emitting the plaintext password would be unsafe, emitting no data at all significantly limits the usefulness of the event for off-chain monitoring, indexing, and auditing purposes.

## Impact

- Off-chain services cannot reliably track meaningful state changes
- Reduced transparency for monitoring and debugging
- Limits usefulness of emitted events for analytics and alerting systems

This issue does not introduce a direct security vulnerability but affects observability and operational quality.

## Proof of Concept
```javascript
event SetNetPassword();

function setPassword(string memory newPassword) external {
    s_password = newPassword;
    emit SetNetPassword();
}
```

The emitted event provides no information about who changed the password or what was changed.

## Recommended Mitigation

Enhance the event to include safe and relevant metadata, such as the caller address and a hash of the password:
```javascript
event SetNewPassword(address indexed caller, bytes32 passwordHash);

function setPassword(string memory newPassword) external {
    s_password = newPassword;
    emit SetNewPassword(msg.sender, keccak256(bytes(newPassword)));
}
```

This approach improves traceability without exposing sensitive data.
