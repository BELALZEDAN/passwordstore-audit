### [M-01] Sensitive Password Stored in Plaintext On-Chain (Confidentiality Violation)

## Description

The contract stores the password directly on-chain in the s_password state variable as a plaintext string.
Although the variable is marked as private, Solidity’s private visibility only restricts access at the contract level and does not provide data confidentiality.

All on-chain storage is publicly accessible and can be read by:

- Blockchain explorers
- RPC providers
- Archive nodes
- Anyone inspecting contract storage directly

As a result, the stored password is not truly private and can be retrieved by third parties without interacting with the contract.
```javascript
string private s_password;
```

## Impact

Sensitive information intended to remain confidential can be exposed to unauthorized parties.
This undermines the contract’s stated goal of securely storing a private password and may lead to:

- Leakage of sensitive credentials
- False sense of security for users
- Violation of privacy expectations

While this issue does not allow direct privilege escalation, it represents a fundamental design flaw in handling sensitive data.

## Proof of Concepts

The password can be retrieved by directly reading the contract’s storage slot corresponding to `s_password` using blockchain inspection tools or RPC calls, without calling getPassword.

This demonstrates that confidentiality cannot be enforced for on-chain plaintext data.

## Recommended Mitigation

Avoid storing sensitive information such as passwords directly on-chain.
Instead, consider one of the following approaches:

Store a cryptographic hash (e.g., keccak256) of the password rather than the plaintext value

Use off-chain storage combined with on-chain verification

Leverage encryption schemes where only encrypted data is stored on-chain and decryption occurs off-chain

Clear documentation should also be provided to ensure users understand the privacy limitations of on-chain data storage.
