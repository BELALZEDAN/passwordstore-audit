### [I-02] No Ownership Transfer Mechanism

## Description

The contract assigns ownership during deployment by setting `s_owner` to `msg.sender` in the constructor. However, it does not provide any mechanism to transfer ownership to another address after deployment.

While this may be acceptable for very simple or throwaway contracts, most production contracts include an ownership transfer mechanism to support key rotation, recovery, or changes in operational control.

## Impact

- Ownership is permanently locked to the deployer address
- Loss of the owner's private key would permanently lock access to critical functions
- Limits contract flexibility and long-term maintainability

This issue does not introduce an immediate security vulnerability but represents a design limitation.

## Proof of Concept
```javascript
constructor() {
    s_owner = msg.sender;
}
```

There is no function allowing `s_owner` to be updated after deployment.

## Recommended Mitigation

Add an ownership transfer mechanism, such as:
```javascript
function transferOwnership(address newOwner) external {
    if (msg.sender != s_owner) revert PasswordStore__NotOwner();
    require(newOwner != address(0), "Invalid new owner");
    s_owner = newOwner;
}
```

Optionally, emit an `OwnershipTransferred` event to improve transparency.
