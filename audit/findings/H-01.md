### [H-01] Missing Access Control on `setPassword` Allows Unauthorized Password Modification

## Description

The `setPassword` function is intended to allow only the contract owner to update the stored password, as stated in the function documentation. However, the function does not enforce any access control and can be called by any external address.

As a result, any arbitrary user can overwrite the stored password, violating the contract’s core security assumption that the password remains private and owner-controlled.
```javascript
function setPassword(string memory newPassword) external {
    s_password = newPassword;
    emit SetNetPassword();
}
```

## Impact

An attacker can:

- Arbitrarily overwrite the stored password
- Prevent the legitimate owner from relying on the password’s integrity
- Force the owner to read attacker-controlled data

This completely breaks the contract’s intended security model and can lead to denial of service and loss of trust in the system.

## Proof of Concepts

A Foundry-based proof of concept demonstrates that a non-owner can successfully call `setPassword` and overwrite the stored password:

```javascript
audit/poc/H-01_PoC.t.sol
```

The test shows that:

- A non-owner address calls `setPassword`
- The transaction succeeds
- The owner later retrieves the attacker-controlled password

## Recommended Mitigation

Enforce owner-only access control on the `setPassword` function by checking the caller’s address:
```javascript
function setPassword(string memory newPassword) external {
    if (msg.sender != s_owner) {
        revert PasswordStore__NotOwner();
    }
    s_password = newPassword;
    emit SetNetPassword();
}
```
