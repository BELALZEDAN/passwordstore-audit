### [I-03] Unused or Inconsistently Applied Custom Error

## Description

The contract defines a custom error `PasswordStore__NotOwner`, which is used in the `getPassword` function to restrict access to the stored password. However, the same error is not applied in the `setPassword` function, even though that function is expected (based on documentation and contract intent) to be restricted to the owner.

This inconsistent usage may cause confusion for developers and auditors, as the presence of the custom error suggests a broader access control model than what is actually enforced.

## Impact

- Reduces code clarity and consistency
- May mislead developers about intended access restrictions
- Decreases overall maintainability and readability

This issue does not directly introduce a new vulnerability but highlights inconsistent design intent.

## Proof of Concept
```javascript
error PasswordStore__NotOwner();

function setPassword(string memory newPassword) external {
    s_password = newPassword;
}

function getPassword() external view returns (string memory) {
    if (msg.sender != s_owner) {
        revert PasswordStore__NotOwner();
    }
    return s_password;
}
```

The custom error is only enforced in `getPassword` but not in `setPassword`.

Recommended Mitigation

Ensure consistent usage of the custom error by either:

- Applying the ownership check to `setPassword`, or
- Removing the unused error if ownership restrictions are not intended

Example mitigation:
```javascript
function setPassword(string memory newPassword) external {
    if (msg.sender != s_owner) revert PasswordStore__NotOwner();
    s_password = newPassword;
}
```
